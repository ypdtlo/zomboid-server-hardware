# 僵尸毁灭工程服务器配置：按人数和模组选对CPU内存，开服参数与机型选购一次讲清

PZ 的服务端主循环基本跑在单线程上。你给它堆 8 核 16 核，它未必用得上；反过来，4 个人的服只分 2GB 内存，进游戏几分钟就会被卡回主菜单。所以「僵尸毁灭工程服务器配置」这件事的正确顺序是：先算内存和单核性能，再看盘、带宽和防御，最后才谈价格。

下面按实际开服会遇到的顺序拆开讲，末尾给一份可以直接抄的机型对照表。

## 先定三个变量：人数、地图、模组

网上配置推荐五花八门，绝大多数是因为只说了人数，没说另外两项。真正吃资源的是这三样：

1. **同时在线人数**——每个玩家都要同步位置、物品栏和视野内的僵尸状态。
2. **地图规模**——原版地图之外再挂 Mod 地图（Raven Creek、Bedford Falls 这类），内存占用会明显抬高，需要额外留出 2GB 左右余量。
3. **模组数量**——物品模组和地图模组不是一个量级的开销，15 个模组和 100 个模组完全是两台机器的事。

三项组合起来，常见的起步档位大致是这样：

| 场景 | CPU | 内存 | 硬盘 | 备注 |
| --- | --- | --- | --- | --- |
| 2–4 人，原版或少量模组 | 2 核 | 4GB | SSD 30GB 起 | 实测内存占用约 3GB |
| 4–8 人，带模组 | 4 核 | 8GB | 30+20GB | 最常见的一档 |
| 8–16 人，含地图模组 | 4 核 | 16GB | 60GB+ | 玩家分散、车辆多时要盯内存曲线 |
| 20 人以上，重模组社区服 | 8 核 | 24–32GB | 100GB+ | 先小规模压测再扩容，别一步到位 |

几组第三方数据可以互相对照。有 PZ 托管商给出的实用经验是：2–5 人原版 4GB 起步、6–8GB 比较舒服；10–20 人带轻量模组 8GB 起步、10–12GB 舒服；20 人以上重模组 12–16GB 起。另一份 4 核 8GB 机型的实测记录显示，4 人服的进程内存占用落在 5–7GB。两边指向同一个结论：**8GB 是多人 PZ 服现实的底线配置，不算奢侈。**

还有两个细节容易被忽略：

- **Build 41 和 Build 42 别混着算配置。** Build 41 是目前长期世界用的稳定分支；Build 42 的多人还在 unstable 测试分支上，多了动物模拟、多层地下室这些系统，内存需求会比 B41 再高出一截。如果你要试 B42，用独立实例、独立服务器名、独立备份，别拿唯一的正式存档去做升级实验。
- **PZ 官方支持到 32 人，但不代表你的机器撑得住。** 8GB 内存配一颗现代 CPU，跑 8–16 人是比较稳的；把 MaxPlayers 留在默认的 32，等于给自己埋雷。

## 为什么 PZ 更看单核，不是核数

PZ 的服务器循环基本是单线程的，时钟频率和每时钟指令数（IPC）比核心数量重要得多。这一点和大部分人对"服务器"的直觉相反，也是新手照着核数买机器、结果还是会卡的原因。

那是不是 2 核就够了？也不至于。下面这些工作不吃主循环，但会抢 CPU：

- 世界区块的加载和写盘，玩家跑图时最明显；
- 自动保存，人越多、地图越大，保存窗口越长；
- Java 垃圾回收，内存越紧张，GC 触发得越频繁；
- 如果你还挂着模组下载、备份脚本，那就再多一份开销。

所以实际建议是 **4 核 + 高主频**这个组合：主循环吃单核性能，其他活儿留给剩下的核心。用服务器托管行业里的说法，同价位下新一代的 Ryzen 或高主频 i9 机型，跑 PZ 这种负载会明显优于老 Xeon。

## 内存别照抄"每人多少 MB"公式

网上流传着各种"每个玩家加 500MB""每人 200MB 加基础 4GB"的算法。这些公式参考价值有限，因为 PZ 的内存占用跟沙盒设置里僵尸数量、物品刷新、地图探索范围强相关——同一个 8 人服，物资刷新调高和调低可能是两三 GB 的差距。合理的做法是：**先给一个够用的基线，再按实际沙盒规则和模组清单去压测调整。**

服务端的 Java 堆内存参数也要一起对。用 Docker 镜像部署时对应的是 `Memory` 这类环境变量（常见写法 `Memory=4096`），直接跑 SteamCMD 的 Linux 服务端则要看 `ProjectZomboid64.json` 里的 `-Xmx`。经验值：**堆内存设成机器物理内存的 60%–70%，剩下的留给系统、磁盘缓存和线程本身的堆外占用。** 8GB 的机器把 `-Xmx` 顶到 8G，最后往往是被 OOM Killer 干掉。

> 一句话原则：内存是 PZ 服务器的硬门槛，单核性能决定它跑得顺不顺，硬盘和带宽决定它稳不稳。三者的优先级就是这个顺序。

## 硬盘、带宽和防御

**硬盘**：基础服务端文件约 2GB，但加上模组、存档和日志，10GB 是比较合理的起点，重模组服 30GB 起步不夸张。一定要 NVMe 或 SSD——PZ 玩家跑图时会持续读写世界区块，机械盘会让整个服的响应变得黏糊。

**带宽**：PZ 的流量需求不算高，10Mbps 上行带 4–8 人基本没问题。要留意的是"上行"这个指标，以及不限流量和限流量两种模式的区别。

**防御**：服务器 IP 一旦公开，被扫、被压测是常态。国内节点普遍带 DDoS 防御，但不同机房规格差得多，有 100G、150G、200G 之分，购买时要看清页面标注的具体数字，别默认所有机型都一样。

## 从购买到进服：几个必踩的坑

**端口。** PZ 服务端配置文件里的 `DefaultPort` 默认是 16261，`UDPPort` 是 16262。NAT 机型需要在控制台建映射规则，把内网端口映射到公网端口上；有独立公网 IP 的话可以直接用。记得防火墙和云平台安全组两边都要放行。

**模组列表要同步。** PZ 的模组要在两个地方登记，`Mods=` 和 `WorkshopItems=` 是两个独立的列表，两处不一致就是"进服就掉线"的最常见原因。加模组前先确认服务端和客户端版本对得上，地图模组还要注意加载顺序。

**`MaxPlayers` 按实际配置设。** 游戏默认是 32，留着小配置机器硬扛 32 人的名额，性能和体验都会打折。按你买的套餐设成 8 或者 16。

**`KeepPauseEmpty` 打开。** 没人在线时让模拟停下来，CPU 和内存占用都会降下来。用动态计费的话，这直接关系到账单。

**升级配置不用重装。** 雨云支持随时升降配置，存档、设置和数据都会保留，按新配置计费。所以起步买小一点、观察一两周再决定加不加内存，是更省钱的路线。

## 常见问题

**4 核 8G 能带几个人？**
原版或少量模组，8–16 人比较稳；模组数量上去之后，瓶颈会先出现在内存上，而不是 CPU。

**必须上高主频 CPU 吗？**
优先考虑。PZ 主循环吃单核性能，同价位下高主频机型带来的流畅度提升，通常比多买两个核心更明显。

**2 核 4G 能开吗？**
能，适合 1–4 人。有实测记录显示 15 个模组的 4 人服内存占用约 3GB，运行平稳。但把人数或模组往上加之前，先规划好升级。

**内存到底怎么估？**
先按"4 人 4GB、8 人 8GB、16 人 16GB"这个粗线起算，再根据地图模组和沙盒设置往上加 2–4GB，然后用真实配置压测一轮。别迷信固定公式。

**服务器卡顿一定是配置不够吗？**
不一定。中文用户遇到的一部分卡顿来自线路延迟，国内机房在这点上比海外节点有优势。选节点时优先考虑玩家所在地域，而不是只看价格。
